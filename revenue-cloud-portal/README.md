# DeepHealth Revenue Cloud Portal

React storefront over the DeepHealth Salesforce org: browse the *DeepHealth Product Catalog*, fill a cart, then
**Create Quote** → the button becomes **Update Quote** and every later cart change updates the *same* Salesforce quote.

```
Browser (React)  ──/api──▶  Node proxy (server/)  ──▶  Salesforce
                            holds the credentials       SOQL  (products, prices, selling models, attributes)
                                                        Apex REST /services/apexrest/api/quotes/  (create / update / get)
```

The proxy exists so the OAuth client secret never ships to the browser (the API document flags the old hard-coded
secrets as a risk). It also re-prices every cart line from the Standard Price Book, so the browser can't choose prices.

## Run locally

```bash
npm install
npm run build && npm start      # http://localhost:8787   (production mode)
# or: npm run dev               # Vite on :5173 + API on :8787
```

With no `SF_CLIENT_ID` / `SF_CLIENT_SECRET` in `.env` the server uses your logged-in Salesforce CLI session
(`SF_CLI_ORG`). The CLI makes the calls itself; the access token is never read. **Local development only.**

## How quote create/update works

| Cart state | Button | Call |
|---|---|---|
| no linked quote | **Create Quote** | `POST /api/quotes` → Apex `POST /api/quotes/` |
| quote linked, cart changed | **Update Quote** | `PATCH /api/quotes/{id}` → Apex `PATCH /api/quotes/{id}` (same quote, line items replaced) |
| quote linked, nothing changed | Update Quote (disabled) | — |
| quote Approved/Rejected/Converted | disabled + "Start a new quote" | Salesforce only allows line-item edits in Draft/Pending |

The quote id + cart are kept in `sessionStorage`, so a refresh keeps the link. A synchronous guard means
double-clicking can never send two requests. No tax is added: Salesforce holds no tax rate, so the quote is saved with Tax = 0 and the
total equals the subtotal.

## Bundles

Products with `Product2.Type = 'Bundle'` get a **Components (N)** button. It opens `#/bundle/{id}`, which lists the bundle's
children (`ProductRelatedComponent`, grouped by component group, showing Required / Default / price-included tags and
the default quantity). Tick any of them and press **Add selected to cart**: the bundle is added as a line and the chosen
children are nested under it (each at its own Standard Price Book price). Nested bundles have their own Components icon
(`#/bundle/{outer}/{inner}`), so their components land under the right bundle. The bundle card's own **Add** is unchanged.
Children that are not in the catalog and have no price are listed but can't be selected.

On Create/Update the quote API saves flat lines; the server then creates a native `QuoteLineRelationship` for every
component (parent line → child line, with the `ProductRelatedComponent`, relationship type and "included in bundle
price" flag). Salesforce fills in `ParentQuoteLineItemId` itself, so the quote's Lines tab shows the components nested
under their bundle. Removing a bundle in the cart removes its components.

## Product attributes / Configure Product

The catalog query includes `ProductAttributeDefinitions` (API v62.0+; active, non-hidden attributes only). Products that
have attributes get a **Configure** button → `#/configure/{id}`: one field per attribute (picklist → dropdown, checkbox,
text/number), required markers, defaults from Salesforce, quantity and an **Add** button. Direct **Add** on the product
card still works without configuring.

A cart line is *product + attribute choices*, so the same product can be added several times with different
configurations (e.g. AI Modality = Lung and AI Modality = Breast). The quote API has no attribute field, so after every
Create/Update the server writes the choices as native `QuoteLineItemAttribute` records (attribute definition, value and
picklist value), which the Salesforce quote screen shows in the line's **Attributes** panel.

The structure and attribute records are written in one all-or-nothing standard REST call (API v67.0, `SF_RECORD_API_VERSION`).
If it fails the quote is still saved and the user is warned. The integration user needs create access to
`QuoteLineRelationship` and `QuoteLineItemAttribute`.

## Public deployment

### Render (see `render.yaml`)

1. Push the repository to GitHub (`.env`, `node_modules` and `dist` are git-ignored).
2. Render → **New + → Blueprint** → pick the repo. If this folder is a subfolder of the repo (as in
   `keerthi-g376/deephealth-portal`), set **Blueprint Path** to `revenue-cloud-portal/render.yaml` (the file, not the
   folder); the blueprint's `rootDir` makes Render build inside that folder. Service name: `deephealth-portal`.
3. When prompted, enter `SF_CLIENT_ID` and `SF_CLIENT_SECRET` (the Consumer Key / Secret of the Salesforce app that has the
   **Client Credentials flow** enabled with a run-as user). `SESSION_SECRET` is generated by Render.
4. Open `https://deephealth-portal.onrender.com`. The free plan sleeps when idle, so the first load after a pause is slow.

Any other Node host works too: build `npm install --include=dev && npm run build`, start `npm start`, same env vars.

The run-as user needs: access to the `QuoteRestController` Apex class; read on Product2, PricebookEntry, the catalog objects,
`ProductRelatedComponent`, `ProductAttributeDefinition`, `AttributePicklistValue`; create/edit/delete on Quote and
QuoteLineItem; **create** on `QuoteLineRelationship` and `QuoteLineItemAttribute`.

### Public mode (automatic when `SF_CLIENT_ID`/`SF_CLIENT_SECRET` are set, or `PUBLIC_MODE=true`)

There is no user login, so anyone with the link can browse and build quotes. To protect the org:
- a visitor can only open/update quotes **created in their own browser** (ids kept in a signed, HttpOnly, Secure cookie;
  forged or foreign quote ids get `403`);
- at most 10 quote creations per hour and 120 API calls per minute per client address (`429` beyond that);
- the product catalog is served from a 60-second cache instead of querying Salesforce on every visit.

Quotes made before a visitor's cookie existed (or after it expires, 7 days) can no longer be updated from that browser;
"Start a new quote" creates a fresh one.

## Known backend behaviour (existing `QuoteRestController`, unchanged)

`PATCH` deletes the quote's lines and then re-inserts them, without a savepoint. If the insert fails, the quote is left
with no lines. The portal validates prices before calling Salesforce and keeps the cart client-side, so pressing
**Update Quote** again restores the lines. A `Savepoint` / `Database.rollback` in the Apex would make it atomic.
